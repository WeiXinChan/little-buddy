# 瓦力 V2 需求基线

状态：交接前整理，尚未下发 Multica，尚未开始实现。依据本次需求讨论及用户逐项确认；后续更改须保留决定来源，不将试用值写成实测结论。

配套文档：[自动化验收方案](v2-acceptance.md) · [Multica 交接计划](v2-multica-handoff.md)。V1 历史依据为 [V1 验收记录](v1-acceptance.md)，旧版需求中的年龄、玩法、人工测试和家长入口范围不代表 V2。

## 一 已确定范围

### R01 定位与年龄

面向 5–8 岁儿童，默认表达接近 5–6 岁容易理解的程度。孩子唤醒后可以聊天、一起玩、共同编故事，随时插话、改规则或换话题。孩子的想法优先，不强求完成游戏，不依赖识字。根据本次互动调整难度，不凭声音推断年龄或身份。

V2 优化 V1 的界面、对话、陪玩和可靠性。本次不增加 ESP32、底盘等硬件范围。

### R02 日常界面与主动性

- 常态是占据主要屏幕的两只大眼睛，表达倾听、思考、说话、等待、故障和待唤醒状态。日常不常驻大量按钮、菜单、设置或调试信息。
- 主要操作通过语音完成。仅在唤醒后主动提议玩法；孩子已经表达想法就顺着孩子，只唤醒没有续说时可提出一个轻量邀请，不朗读游戏菜单。
- 不在未唤醒时自主搭话，不频繁推荐游戏，不反复催促沉默的孩子。
- 图片按 R09 临时展示，结束后恢复眼睛。

### R03 统一聊天与四类陪玩

聊天、玩法理解、角色交换、规则变化和话题切换统一由主 LLM 结合上下文处理，不要求固定口令或预先进入模式。系统负责事实保存、可靠执行和取消过期操作。

| 首批玩法 | 范围 | 必须保持的体验 |
| --- | --- | --- |
| 轮流猜与描述 | 动物、物品、食物等；双方轮流出题 | 谜底一致，允许追问、提示、交换角色 |
| 一起编故事 | 轮流接续，孩子决定发展 | 人物、设定、情节连续，每次推进适量内容 |
| 角色扮演与小冒险 | 恐龙、飞船、探索等 | 接受孩子的行动和设定，不限制为预设选项 |
| 联想与轮流说 | 分类、起名字、用途和创意联想 | 接受合理的新奇答案，避免机械判错和重复 |

允许修改规则、放弃一局、转换主题和自然跨玩法。变化来自主题、角色、线索、难度和互动方式，不只是固定题库。听不懂时简短澄清，不擅自决定。普通互动一两个短句、一次主要问一个问题；故事分段，给孩子参与和打断的空间。

### R04 角色风格

瓦力是好奇、温暖、有想象力、有轻微幽默感且可靠的机器人伙伴。有主意但不争夺主导权，不靠装傻、错误知识或捉弄孩子制造趣味。

- 声音方向为中性、清亮、自然、适度轻快，发音清楚，不过度幼态，不持续叠加电子或金属变声。具体音色待代理试听和设备验证后选择。
- 角色扮演可在同一基础音色上轻微变化，不突然尖叫、恐吓或大幅提高音量。
- 自称“我”，适量使用“瓦力”；默认称孩子“你”。主动提供的昵称只在本次会话自然使用。默认不反复称“小主人”“宝贝”“乖宝宝”，不要求真实姓名。
- 回应具体，表扬关注观察和尝试，不每轮套用同一种开场、夸奖、追问或口头禅。允许只回应、只接梗或安静等待。
- 不嘲笑口音、错误答案、身体特征，不拿孩子的难过或害怕开玩笑。
- 不编造人类童年、亲历或现场感知；不建立排他关系、秘密亲密关系、恋爱关系或离开后的情感负担。
- 安全求助时保持熟悉声音，语气平稳、表达直接，暂停玩笑与角色表演。

### R05 说话结束与附和

结合声音、表达完整性和当前互动判断轮次，不能只看固定静音时长或字数。

| 情况 | 行为 |
| --- | --- |
| “我觉得是……长颈鹿” | 中间停顿保留续说空间，不抢答 |
| “嗯……让我想想” | 继续倾听，不当作答案 |
| 回答“要换你出题吗”的“嗯” | 作为有效同意处理 |
| 故事中轻声“嗯”“对” | 判断为附和时继续讲，不额外追问 |
| “对，但是……” | 听完整补充和纠正 |
| 瓦力尾音期间的短回答 | 不因播放重叠或识别晚到丢弃 |

等待用眼睛反馈，不反复说“我在听”“然后呢”。孩子再次开口就继续聚合表达。没有识别文字不等于没有说话；明确听到表达但识别失败时，应等说完再确认。普通背景声、笑声或咳嗽不反复触发识别失败提示。

### R06 打断与取消

- 支持“停”“不”“等等”等短表达，不要求最少三个字。孩子重复机器人的词也可能是正常参与。
- 明确附和可继续；明确插话优先停播；一时不确定可先暂挂，保留位置并继续收音。
- 确认真正打断后取消不再需要的生成、排队音频和图片，迟到结果不得影响新一轮。
- 只有确认非插话或噪声才可恢复；明确说过“停”后，不因后续安静自动续播。
- 打断后无需重新唤醒才能说完。瓦力准备开口时孩子续说，应撤回未播出的回答。
- 停播尽量由本地完成，不能等待主 LLM 完整理解才让出说话空间。多人参与不限制谁能要求停止。

### R07 会话暂停与结束

| 表达或行为 | 处理 | 上下文 |
| --- | --- | --- |
| “停”“等等” | 停播并继续听 | 保留 |
| “不玩这个了” | 结束该玩法，交还选择权 | 保留并标记结束 |
| “换一个”“讲故事吧” | 自然切换 | 保留相关内容 |
| “我去拿玩具”“等我一下” | 安静等待，不催促 | 临时保留 |
| 持续无有效互动 | 进入待唤醒 | 保留至期限 |
| “再见”“我要睡觉了”“你休息吧” | 简短告别，结束会话 | 清空 |

正在说话、播放故事或处理有效请求，不按普通沉默计时。短暂返回可接续，也允许直接新话题；过期不假装记得。应用重启不承诺恢复旧会话。明确交接给另一个孩子及多人退出见 R16。

### R08 本次上下文与实际播放

聊天、故事和玩法共享本次上下文。保留近期对话、本次摘要、角色、规则、秘密答案、已给线索、情节及中断情况。切换主题不整体清空；长聊可以压缩早期内容，但不能丢失当前事实。

生成、开始播放和确认播完必须区分。已生成但未播出的谜底不算揭晓；段内打断无法准确判断时保留“不确定/未说完”，不得把整句都记成孩子已听到。重试、取消、恢复和图片展示均遵守这一事实。

### R09 图片的时机与故障体验

- 猜谜揭晓后、已讲到的故事关键画面或孩子明确要求看时可以展示。普通聊天、联想和猜谜过程中默认保持眼睛。
- 准备好不等于允许显示：答案实际说出后才能展示揭晓图，不提前透露剧情。
- 优先使用检查过的插画库，特殊想象再即时生成；一次以一张为主，不持续生成整套故事。默认不实时网上搜图。
- 生成不阻塞对话，不用持续转圈页面、不反复承诺“马上好”。任务实际启动后才可告知正在准备。
- 返回时检查话题与会话是否仍有效；取消或换人后的旧图不弹出。孩子说话时不以播报提醒抢话。
- 装饰性配图失败可安静跳过；明确要求的图失败要简短交代。不能用不符合要求的现成图冒充成功，不持续自动重试。
- 支持“再看一下”“收起来”“再看一会儿”和修改设定。展示期间仍能交谈和打断，不依赖关闭按钮。

### R10 图片质量与首批素材

首批约 60 张，类别规划如下；具体对象清单留到设计阶段。

| 类别 | 规划量 |
| --- | ---: |
| 动物 | 24 |
| 食物与日常物品 | 16 |
| 交通与探索工具 | 8 |
| 自然与故事场景 | 8 |
| 常用幻想角色 | 4 |

采用温暖清楚的二维绘本插画：轮廓清晰、稍圆润、大色块、少量柔和阴影，明快不刺眼，默认不含文字、水印、对话框或按钮。避免在素材库中混杂写实照片和明显不同画风。屏幕切换不闪烁、不突然刺眼，实际比例不拉伸或裁断关键主体。

揭晓图主体明确、背景简单，现实知识特征准确；故事画面突出一个地点或事件。特殊幻想与现实知识图分开处理。首版优先单一主角、明确动作和少量细节，不要求复杂多人精确构图。

同一故事内，主角物种、主要颜色、标志性特征和重要配饰保持一致；孩子主动修改时更新。姿势和非关键背景变化允许。角色描述仅在本次会话保留。

不安全、主体错误、明显结构异常、遗漏关键设定或角色严重不一致的图片不强行展示；可以复用已有图或保持眼睛。素材以外仍能正常聊天和陪玩。

### R11 故障与恢复

- 区分没说完、没听清和意思不明确。利用听到的部分，仅确认缺失信息；候选不能凭空猜。
- 连续两次没听清时换更容易回答的方式，不反复要求整句重说，不责怪孩子。
- 网络短暂波动在总等待预算内自动恢复。需要时提示一次，不用占位语假装已有效回答。
- 自动重试最多一次，限原请求仍有效且不会重复操作的情况；重试不重置总等待时间。
- 断网有本地可用提示，不假装持续理解，不积累离线新话等恢复后集中补答。暂停或取消仍可靠。
- 已告知失败、进入待唤醒或换话题后，不播放晚到的旧答案。未成功处理的话不假装听懂。
- 语音中途失败按已播情况恢复，可从合适短句重说，不整段重复或跳过关键内容。
- 不对孩子播报错误码，不用“我坏了”“我很难过”等表达增加情感负担。

### R12 儿童内容边界

身体、出生、差异、死亡、疾病、失去宠物、愤怒、孤独、家庭和同伴矛盾不是一律拒绝的话题。用准确、简短、适龄、尊重的语言回应，接受感受，不羞辱好奇；尊重不同家庭、文化和信仰。轻度幻想冒险可以继续。

禁止色情和儿童性化内容、恐吓、血腥虐待、可执行的自伤伤人或危险操作、欺凌歧视协助、隐瞒现实危险的帮助，以及诊断、自行用药和药量指导。故事、图片和工具操作遵守同一边界，虚构外衣不能绕过限制。

危险请求先接住情绪或意图，短句说明边界，再给安全替代或现实求助方向。普通问题不例行转交家长；持续困扰引导可信任大人；即时危险优先停止游戏并获取现实帮助，不因追问细节而拖延。

可信任大人不默认等于父母。疑似受伤害披露应认真听、不责怪、不审问、不索要证明、不要求与伤害者对质，不承诺永久保密或谎称已通知别人。只问当前安全和求助所需信息。暂不自动通知任何联系人。

不建立排他依赖、恋爱或秘密亲密关系，不主动索要住址、学校、联系方式、密码、私密照片。安全判断不可用时不得直接放行未经检查的内容；儿童表达危险经历不能被当作违规输入直接断开倾听和求助通道。

### R13 数据保留与隐私

以下期限约束我们控制的客户端及后端；供应商的接收、保存、训练、人工审阅、缓存及备份另行逐项核实，不能把本项目不保存描述成整条链路不保存。

| 数据 | 默认规则 |
| --- | --- |
| 唤醒前环境音 | 优先本地唤醒，必要短时循环缓冲，不持续上传和保存 |
| 原始儿童语音 | 默认不保存录音，当前识别和必要处理完成后释放 |
| 对话正文、摘要、玩法事实 | 本次会话内保留，明确结束或临时保留过期后清空 |
| 合成语音 | 播放完成或对应任务取消后释放 |
| 本次生成图和描述 | 随会话结束或超时清理 |
| 无正文运行日志 | 最多 7 天，自动清理 |
| 主动提交的问题材料 | 原单提交成功起最多 7 天；主动撤回见 R15 |

运行日志可记录必要版本、临时请求编号、阶段、耗时、用量、错误类别、重试、取消和播放进度；不含完整提示词、对话、模型回答、工具结果、音频、声纹、身份、敏感披露和凭证。错误报告、监控、转储、缓存和临时文件均需检查。安全事件不自动触发正文保存。

设备日志默认本地，不持续上传整份日志；主动反馈只附必要时段。先用问题描述、过程日志、成人复现或构造样例定位问题。真实内容样本采集不属于默认 V2 能力。

不将真实儿童会话用于训练或改进样本库，不建立长期画像、聊天回放或默认家长日报。通用素材和预录提示不属于儿童会话材料。支持清理当前会话、本地日志和已提交材料，不承诺虚假的“永远只有我们知道”。

### R14 家长管理入口

2026-11-28 用户明确决定移除 PIN 家长控制，并已删除手机系统锁屏密码；此决定取代此前 6 位 PIN、设备凭据验证、PIN 恢复与防猜要求。进入管理不再初始化、输入或重复验证 PIN，也不依赖系统锁屏。当前直接管理入口不提供身份鉴别或防止儿童修改设置的 PIN 保护。

“瓦力瓦力，进入管理页面”等自然语音入口及右下角长按备用入口进入家长管理；非角落长按不打开文字求助页，不增加常驻按钮。进入管理暂停儿童播报、对话收音及迟到输出，管理期间的话不进入儿童上下文。退出回待唤醒，不自动续播旧话。

管理区含设置、隐私与数据、帮助与反馈，显示有用连接状态及常用设置。必要音量上限、适度语速及经过验证的音色可以调整；不暴露模型、密钥、token、提示词或复杂阈值，不提供关闭儿童安全的开关。已发行的设备预置连接直接使用，已保存连接不重复导入或要求手填技术字段。连接设备私钥、公钥绑定、传输认证及 App 私有安全存储仍保留；移除 PIN 不等于移除服务端鉴权。

孩子仍可以停播、结束会话、控制图片和在设置上限内调音量。清理日志、提交/撤回问题及修改长期配置在管理区完成，清理操作说明范围并一次确认。管理页面代际、操作期限、失焦取消、材料期限及原子提交约束继续生效，不宣称其构成 PIN 身份保护。

### R15 问题材料管理

“我提交的问题”首版只管理本设备提交的问题，不新增跨设备账号体系。展示编号、提交时间、类型、家长说明、附带日志范围、状态、回复和预计删除时间。不包含儿童聊天历史或录音。

提交允许不附日志，附加时清楚说明范围；不默认录音、视频、截图或全部 7 天日志。提醒避免填写不必要的个人信息。反馈类别包括识别、接话、打断、声音/网络、图片及其他。

状态：待发送/发送失败、已提交、处理中、已回复、删除请求待发送、正在删除、已删除。状态必须真实，已回复不等于已解决。回复在家长区查看，不向孩子语音播报，不新增短信或邮件通知。

首版提供“撤回并删除”整单操作，不做保留材料的假撤回或长期回收站。一次确认后删除本单说明、附带日志副本、补充、回复及内部备注，不影响设置和其他问题。源运行日志独立按 R13 保留，不能暗示撤回已删除全部日志。

**已确定的删除要求，不是试用参数：**

- 服务端收到撤回请求后立即停止处理和排障人员访问。
- 完成删除的截止时间为“收到请求后 24 小时”和“原单提交后 7 天”中的较早者。
- 查看、回复、补充材料不重置原单期限；未解决也不无限延期。
- 未上传草稿取消即清除；上传途中撤回同时处理服务端已收部分；离线请求显示待发送，不冒充已删除。
- 只在服务端确认完成后显示已删除。失败或逾期如实显示并后台排查，原 7 天到期机制独立执行。
- 删除中的列表仅保留必要编号、状态和时间；完成提示不形成超过原单期限的永久历史。
- 缓存、下载副本、搜索索引遵守同一期限，不进入长期备份。仅必要人员可访问，不复制到训练集或画像。
- 可保留不含个人内容及可回溯标识的技术结论，不保留原始材料的替代副本。

接收平台、维护者入口与处理责任待确认。人工首次回复和修复时限不与删除时限混淆，试用阶段不承诺未经资源确认的固定响应时间。

### R16 多人参与与换人

一台设备一个共同会话，支持少量孩子轮流参与，不做声纹识别或多儿童独立账号。昵称和角色仅是本次约定，不能当作已验证身份。

- 共享玩法记住角色、职责、规则和进展。归属不清时只作必要确认，不每句询问身份。
- 重叠听不清时请轮流说，不把混合声音拼成一个人的意思；不同想法可协商先后，不让最大声音永远占优。
- “换我出题”“我当船长”是角色交换；“我也参加”是加入；明确“换个人自己玩”默认新会话。含糊“换我”简短确认。
- 明确交接清空前一人的正文、摘要、个人信息和旧任务，保留设备设置，不复述前人的私事。
- 明确接续共同故事时，只携带适合分享的游戏进展，不携带私人聊天，不泄露隐藏谜底；无法可靠分离时重新开始。
- 无身份识别不能保证自动发现所有换人，不能假装能可靠分辨每个声音。
- 多人中“我先退出，你们继续”不结束其他人的会话；“我们都不玩了”结束；不清楚时问一次是否继续，然后按等待规则处理。
- 任何参与者可要求停播，安全求助不排队；自称家长不替代 PIN。不评判谁更乖、更聪明，不配合排挤。

### R17 性能与成本

先保证安全、理解、接话和上下文，再在达标方案中比较成本。主方案以流式 ASR、统一主 LLM、分段 TTS 为评测起点，端到端实时语音可对照；具体供应商、模型和版本待自动化与代理评测确定。选定后固定版本，升级复测。

避免长时间推理作为日常默认，不每轮先便宜模型试答再贵模型重答。减少重复意图调用、无效生成和无限增长的历史；已取消任务的费用以真实账单为准。不为省钱绕过安全或延长儿童数据保存。

**家长端不做预算、充值、额度设置或提醒页面。** 用户已在后端平台设置预算；只需适配真实的额度不足状态。不能伪装为断网或让孩子无限等待。每小时成本是内部优化目标，不是应用内硬截止或售价。

### R18 组织与验收责任

**Multica 负责组织自动化测试、代理检查、真机执行、修复和回归。用户只体验 V2 最终完整产品，不承担中间测试。**

不安排用户/家长/儿童提供录音、分项点测、反复试听、调参数或补测。不把缺失测试包装成“请用户验收”。音色、素材和中间方案由代理先完成筛选与检查。自动化及代理不能覆盖的限制如实报告，不冒充真实儿童测试，也不转成用户测试清单。

最终体验中发现的问题由 Multica 复现、修复并补充自动化回归。V1 的人工测试安排不继承到 V2。

## 二 试用参数

以下是设计起点和优化目标，不是已有实测结果。正式放行时须报告分母、失败、超时和限制，不能仅挑成功样本。

| ID | 项目 | 试用值/目标 | 计时或适用说明 |
| --- | --- | --- | --- |
| P01 | 完整表达后的接话等待 | 0.8–1.2 秒 | 结合语义及声音，不机械静音截断 |
| P02 | 明显未说完的续说空间 | 先给 2–3 秒 | 到时重判，不强制回答 |
| P03 | 明确思考 | 先等 8–12 秒 | 视情境轻问一次；拒绝提示后不催 |
| P04 | 无有效互动后待唤醒 | 约 60 秒 | 正在播放/处理有效请求不按普通沉默 |
| P05 | 临时会话保留 | 约 10 分钟 | 从最后有效互动起，明确结束则清空 |
| P06 | 揭晓图展示 | 5–8 秒 | 答案实际说出后 |
| P07 | 故事图展示 | 10–15 秒 | 可语音延长或收起 |
| P08 | 即时生图等待上限 | 15–20 秒 | 内容过期更早取消 |
| P09 | 无有效回复时轻反馈 | 3–4 秒 | 从确认孩子表达结束起，仅必要时一次 |

| P11 | 唤醒反馈 | 约 300 毫秒内 | 眼睛或声音，测量起点需明确 |
| P12 | 普通回复开口速度 | 中位数 ≤2 秒，P95 ≤4 秒 | 从完整表达实际结束至有效音频，含整链路；占位语不算 |
