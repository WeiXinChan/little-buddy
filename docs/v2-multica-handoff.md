# 瓦力 V2 Multica 交接计划

状态：交接前计划，尚未创建或下发外部任务，未开始实现或执行产品测试。

用户要求：交接给 Multica 之前先汇报。当前只准备可评审材料；本文件中的编号是计划编号，不是 Multica 实际任务编号。报告应包含三份文件、任务拆分、依赖和未知事项，不能把编写计划描述为已安排执行。

依据：[需求基线](v2-requirements.md) · [自动化验收方案](v2-acceptance.md) · [V1 已验收基线](v1-acceptance.md)。

## 一 工作规则

1. 已确定产品边界以 V2 文档为准，不把 V1 固定题库、旧年龄、无家长入口或人工测试安排带入 V2。
2. Multica 组织开发、自动化、代理评审、真机执行、修复与回归。用户只体验最终完整产品，不做过程测试、录音、点按、试听或参数调试。
3. 所有实现任务都对应需求和测试编号；功能完成不等于测试通过。确定性检查和独立代理评审配合，不只依赖实现者自评。
4. 实现与测试可以按契约分工，集成、设备音频和长时测试协调设备及资源，避免并行互相污染。
5. 未核实的平台、设备或供应商能力先标依赖，不伪造完成、不扩大权限、不擅自购买资源或把阻塞转成用户测试任务。
6. 不更改已验收 V1 的安装、配对和生产配置作为准备工作。V2 实现、部署和最终交付须在后续授权执行阶段进行。
7. 原始录音默认不保存，运行日志最多 7 天；问题撤回后的 24 小时/原单 7 天是固定要求，不是可随意调大的性能参数。
8. 不做家长端预算管理；复用用户既有后端预算控制，准确处理额度不足。

## 四 每项任务的完成定义

- 明确覆盖的需求、范围外事项、依赖和真实版本。
- 有具体产物及对应自动化结果；报告样本数、失败、未测和限制，不只附“测试通过”一句话。
- 重要事实、取消、权限、数据和安全有确定性断言或明确独立检查。
- 发现的问题已关联复现与回归任务，旧缺陷不靠人工体验兜底。
- 不包含生产凭据、真实儿童录音、完整会话或超期问题材料。
- 改变试用参数时记录原因和测量结果；不改变固定数据边界或自行增加产品范围。
