## 实际生产路径

`V2VoiceActivity → Capture → VoiceClient/InputGate → /v2/voice → VoicePeer → Session`；输出为 `VoicePeer → VoiceClient → Playback → AndroidTrack(AudioTrack)`，ACK经同一WebSocket返回实际Session。生产层不导入lab或测试状态机。V2入口不读取V1端点或凭据，不接受intent extras设置端点/密钥；M05/后续受认证配置方调用内部`startVoice`。本阶段独立入口显示待配置，不能当最终儿童界面或可用成品。独立包`com.littlebuddy.sim.v2`，debug签名，当前v2Debug仅打包已授权OPPO目标arm64-v8a，不能用于覆盖V1；尚未集成正式配置和发布签名。

16kHz单AudioRecord持续本地KWS，未唤醒不上传；唤醒后有限环形缓存按绝对采样位置交接。KWS迟报时，先把缓存tail后的音频送入实际VAD，确认后从唯一游标上传，owner延迟不会引用复用的录音数组。V2忽略V1 SpeechDetector的END；初始噪声底取36为待真机校准假设，不是童声效果证据。V2使用VOICE_COMMUNICATION，并尝试系统AEC；API可用不代表声学双讲已通过。

`InputGate`默认P01=1000ms、P02=2500ms、P03=10000ms，分别可配在批准试用区间。短静音300ms只触发语义probe；完整句才按P01提交；未完句到期再次probe，不能强制回答；思考最多发一次上下文邀请请求，不强制seal。后端`thinking_prompt`目前仅确认等待，实际自然语言轻问和拒绝后不催留M05接入。`endpoint`为异步LLM适配口，接收完整累计ASR和已播上下文，返回`completion`与`meaning`。同一“嗯/对”的上下文判定、语义等待质量及确认噪声质量须在M05实际模型及后续声学中验证；这里没有词数、关键词或回声文本相似过滤替代语义。

首个真实输入耗尽当次solo资格；单独唤醒500ms无输入才走`wake_solo → answer(None, context)`提议口，一次唤醒仅一次。原声续说递增revision，旧probe/decision被丢弃；提交intent带一次性随机凭据，后端再检查当前revision。续说保留累计音频，延迟分析只留一份最新待查快照。P04为60秒普通空闲回KWS待唤醒，播放/处理/思考不按普通空闲；P05后端600秒正文保留从有效互动计时，心跳不续期。两者独立。

24kHz单声道PCM16。AudioTrack实例UUID、stream代际与服务端身份绑定；head是实际`playbackHeadPosition`无符号帧数，不用写入量、时间或TTS完成冒充播放。计数回退/回绕、路由变化触发撤销。每包最多2400帧，后端最多2包在途，客户端最多24000帧/10包，入口有20帧owner背压，输入累计上限20秒。流式TTS单块有界并一块前瞻，只在句尾完整ACK后提交公开文本；空中间块不占已揭晓事实名额。网络波动下连续性仍待真机测量。

取消先清本地binding/队列，逐一尝试mute/pause/flush/stop/release，再发送新epoch的stop，后端撤销旧任务/音频/图像副作用。任一步停止/关闭失败均隔离句柄，禁止静默重建；后端提供者关闭500ms预算，失败则禁用该服务实例，不把超时当已释放。失焦/后台/销毁关闭收播，前台不自动复播；真实权限撤销、锁屏与生命周期释放仍待设备自动化。

R96-04：仅head严格前进记`last_head_progress`。同head新sequence、旧ACK、send、心跳及占位均不能续期；真正半段前进可续期，截止后迟到不能复活。连续跨段ACK即使在同head才提交后段，也不能把确认时间伪装成新进展时间。R97修正后首有效响应预算为同一个15秒：从Capture最后有效语音帧的观测边界起，覆盖owner派发、传输、ASR、语义probe、普通轮次等待、生成/TTS及有效播放ACK；probe/seal/stop/retry都不能重置。线上只发送非负age_ms，不接受客户端绝对/未来时钟延长。明确thinking时间独立记账，真正续说更新合法表达边界。不能将思考时间混入普通回复统计，也不把软件边界时间冒充声学实测。

## 提供者契约及门控

`recognize(16000)`、`answer(text_or_None, authoritative_context)`、`synthesize(approved_text,24000)`都是async context manager；`endpoint(text, context)`为async，严格返回：

```json
{"completion":"complete|incomplete|thinking","meaning":"new_turn|stop|noise|backchannel|thinking|unknown"}
```

`policy.input/segment`必须来自已审定安全实现。供应商异常只能通过`VoiceFault(quota|network|timeout|safety|voice)`传脱敏分类，不猜测额度；未分类错误一律voice，不回显供应商异常正文。本阶段夹具的policy仅允许合成数据，不是儿童安全实现。D05满足前不接真实儿童数据；供应商模型、流式ASR服务、正式配置、安全审核、自然语言本地失败提示及跨模型比较仍留对应M05/M10/M12。M04当前ASR按有限累计快照分析，尚不宣称供应商流式ASR会话已验证。

## TITA-97定点修正及执行责任

R97-01：新增生产ResponseBudget；Capture在录音线程取得observedAt，owner派发保留该值，VoiceClient/Gate本地看门狗在播放泵前检查；input传speech/age_ms，服务端以自己时钟减非负age建锚。最后有效语音后300ms静音、probe、seal和stop不再续期；实际续说可更新边界，明确思考的暂停独立累计。旧序号/旧revision不能修改新预算。绑定旧输出的ACK不能满足新表达预算。首个安全批准的真实TTS完整PCM块ACK可解除首响应等待，但只有整句末块确认才能提交整句公共事实，占位不走此路径。普通回复的软件时间锚并非外部声学测量。

R97-02：Playback在读native head前以及读取后、任何更新progress/写入/ACK前均按旧progress检查60秒截止；截止后迟到head不能复活。评审Review97Test原件纳入测试，59999ms进展续期配对保留；另测过期tick不得读取head、写入或发ACK。

R97-03：NativeEvidence来自真实AudioRecord.recordingState、读帧数、session及停止/释放后native状态；播放器来自生产AudioTrack绑定UUID、实测head及同句柄StopResult。HOME、锁屏和权限准备都必须先requireRunning，两资源任一启动失败不能视为释放成功。HOME/解锁后验证native读帧不增、binding空，只有显式新连接才可重新启用。TLS正例等待后端最终ACK消费后的reply_end(head/public_facts)回执，抑制最后ACK的负控不得得到同一完成回执。这里只回传无正文计数。
