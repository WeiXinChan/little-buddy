# Missing legacy binding: isolated local recovery (code28)

Device code27 established only this: original store present, legacy owner alias/certificate absent, original local marker absent; binding selection failed before domain/key/decrypt. It does not establish loss of the old AES or registered SSH key. Original device reports and all prior APKs are retained.

The exact observed combination now selects an independent local namespace, initialized solely from the already-issued private preset and default playback settings. The old PIN settings are **not recovered or migrated** when their AAD is lost. Original v2-parent-v1 file/backup/AES alias, owner alias and SSH identity are never overwritten, deleted or regenerated. Readable legacy paths continue their existing migration. An alias still present with a missing certificate does not qualify for automatic recovery.

New file `v2-parent-local-v1`, AES alias `little-buddy-v2-parent-local-v1`, stable AAD `little-buddy:v2:parent-local:1`; AES256/GCM, no user-auth requirement, noBackup/app-private. Selection marker `v2-parent-local-selected-v1` contains exactly one byte1 and uses AtomicFile. New record commit/readback and a usable connection precede marker publication. Existing new namespace or a valid selection marker takes precedence on restart and does not re-query missing legacy credentials. A record committed before a marker-write failure is validated and selected on retry without rewriting or reimporting. A key created without a committed record, a selected but missing namespace, corrupt marker/ciphertext or missing new key fails closed; no reset/re-key is attempted. Unknown/partial initialization remains available for diagnosis, preserving evidence.

No issued account/token, SSH alias/public key/server registration changes. No new preset means no fresh recovery key/record/selector. Existing committed new connection remains usable without a new preset. `LEGACY_UNREADABLE_ISOLATED` is a fixed enum, never a claim of complete legacy-settings migration.
