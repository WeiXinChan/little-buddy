# M09 独立产品核心与接线边界

基线 main `112e456ff09f619ab5929b486ed73358110ba3d5`。本 PR 是批准范围内的 Kotlin 产品域、真实加密文件存储及故障测试；未接管理 UI、真实工单平台或后台部署。A24–A31、D02/D06、完整 M09 均仍 OPEN。无真机或儿童效果结论，无 V1 改动。

## 三层提交边界（R86-02 同类问题）

1. **本地准备**：在隔离状态副本计算候选状态，将候选写入 `staging`。它由仅存在本次调用内存中的随机 AES-GCM 密钥加密，密钥不落盘。不是可恢复 outbox，不得自动上传；撤销、失败或进程重启即丢弃。此阶段可以阻塞磁盘，但不持 ParentAuthorizer 的锁，也未改变已发布的本地源日志或材料。
2. **核心不可逆决定**：所有准备 IO 完成后，`ParentAuthorizer.accept` 重验同一 intent 的实例、页面代际、闲置及精确 scope。在回调内部同时发布候选状态引用及一次性的 `Committed` 事务对象。没有“先 accepted=true，等 IO 完成后再改数据”的许可。回调不做 IO/解密/网络；内存草稿引用/有界日志缓冲也在此发布/清理。决定之后的写盘是履行该特定事务，不是再次使用 Grant。调用只有在加密文件和账本持久化成功后才返回成功。期间撤销不取消已合法提交的事务；写盘失败封闭当前实例，不返回成功，重启时若两文件不匹配则隔离。提交决定到落盘间进程崩溃，未获成功回执的操作结果未知，不能宣称已提交；重启不自动发送。
3. **提供者接收**：本地提交成功并不等于远端接收。另一个在准备前取得的 opaque intent 到 provider 最终 admission 再重验，不复用本地决定的布尔值。提供者必须把 admission 与自身接收决定原子关联，不能把回调返回值缓存后跨阻塞 IO 再接收；受控上传接受后发生的超时/迟到成功用原幂等键删除补偿。未接入/未经评审的 provider 返回 UNAVAILABLE。网络准备、远端接收、服务端耐久时间和全副本删除，不能由本地代码代证。

根审追加反例用可控 VaultFiles 在 staging replace 阻塞，期间执行 HOME 等价 revoke，然后释放：submit 和 clear 都必须 DENIED，`materials` 密文字节保持不变；重启后不得出现 outbox，源日志仍在。另测已经合法决定后、最终写盘阻塞期间撤销：按该事务真实结果返回。负控实际改回“阻塞 IO 前 accepted 布尔、IO 后发布”，两条测试必须分别失败。

ParentAuthorizer 的集成方必须保证 accept 的检查和短回调原子性、旧页面对象不能在重新进入管理后复活；revoke 不获取核心/IO 锁。当前 production 默认 DenyParentAuthorizer，不复制 PR38 Grant 或锁实现。测试 Authorizer/Provider 仅在 test 源集。默认拒绝并不代替上述核心竞争测试。

## 日志与范围

`record` 只接受 LogStage/LogError 枚举、Int 版本、Long 耗时/用量以及本地受信时钟；未知字段在任何落盘前丢弃，错误类型/超界值不写入。没有任意错误字符串、提示词、模型正文、原音、转写、URL、凭据入口。日志最多 1000 条/256KiB，说明最多 2000 Unicode code points；这些是工程初值，分别限制事件数量、导出大小及人工说明长度，不是新增产品试用参数。材料最多 64 单，整个加密快照最多约 2MiB，超过即失败而非偷偷截断说明。

草稿仅内存，默认纯说明；显式选取起止时间后，预览给出实际首尾、条数、UTF-8/ASCII 字节数。确认绑定草稿摘要、对象引用和版本，说明/选择变化、清日志、重新预览、取消、重启、选定日志到期均使旧确认失效。新产生但没有选中的日志不会被悄悄加入。复制保留原始日志时间，单副本最多到选中最早源条目的七天截止；较新的条目可以保守提早清理。提交材料的其他字段仍按原单期限。

取消释放草稿引用并清零可变日志 ByteArray；Kotlin/Java String 不承诺取证级内存擦除。说明可能含家长自填个人信息，不能宣称匿名。

## 存储与恢复

AndroidFeedbackVault 使用独立 Android Keystore AES-GCM alias 与 `noBackupFilesDir/m09-feedback`。未丢失数据而缺密钥时拒绝重建；不访问配对、PIN、端点配置。manifest 已有 allowBackup=false，本 PR 不修改。Keystore/Android 文件系统实际兼容性和生命周期接线尚待集成验证，本轮 JVM AES-GCM/真实临时文件测试不能代替它。

材料和删除任务在同一认证快照内，独立认证账本绑定整个密文摘要。先账本、后材料原子替换并 fsync；任意中断/旧材料+新账本/缺账本/损坏/错误 key 都 fail closed，不从旧材料自动重建删除事实。stage 只有不可恢复的短暂密文，正常退出和下次 load 清除；物理闪存擦除不作承诺。

**恢复整机/双文件旧快照不是受支持恢复途径。** 无防回滚硬件/外部账本时，两个合法旧文件一起回滚无法仅靠本机密码学检测。恢复入口必须在开放前调用 `quarantineRestore()`，丢弃/隔离整批而非导入；目前没有恢复导入 UI。不得声称本 PR 解决任意宿主快照恶意回滚。L87-01 必需反例特指缺账本旧快照：撤回第 1 天、撤回截止第 2 天、原 7 天前恢复，必须拒绝。

时钟不可用或低于已知持久水位时停止访问，不允许延长截止。普通系统时间不是可信服务器时间；真实 adapter 需要核定服务端不可变时间与可信时钟途径，未满足时不得放行真实材料。

## 状态、截止与删除

只有校验过的 SubmitReceipt 才进入 SUBMITTED。远端处理/回复并未建立公开回调或远程 API；内部 receiveReply 不续期、不能复活撤回或过期条目。上传超时显示 SEND_FAILED；不换新键重发、不重启自动发送。当前核心只自动履行既有删除意图，重新提交/补充/分页/远端列表的 UI 和真实适配仍未开放。

本地撤回先受保护提交耐久意图，正文/日志副本/回复立即从可读域移除。源日志和其他单独立保留。drainDeletions 只持有该单原键的删除权限，不需要继续持有家长 Grant。超时已收的部分上传也按原键删除，迟到 submitReceipt 不恢复已撤回状态。离线/失败不报已删除；只有经评审 adapter 验证全副本回执后才可返回 allCopiesDeleted，客户端布尔或隐藏/软删不合格。

已提交截止严格 `min(submittedAt+7d, firstWithdrawal+24h)`；重复撤回、回复、重试、复制均不改原时间。本机先拒访问可能早于服务端收到撤回，属于更保守界限，不能据此证明服务端已停访问。未经提交的敏感暂存最多 1 小时；响应未知时只留无正文的原键删除任务，最多至创建起 7 天（比未知服务端提交起 7 天保守）。所有条目在原保留上限移除，逾期删除仍未取得证明属于 D06 失败，不能谎报完成。未来真实平台必须独立运行清理和告警，不能只依赖本机任务。

调用方需定期执行 sweep/drainDeletions；核心初始化和受保护列表访问也 sweep。后台调度、独立后端扫描、跨设备凭据发行/吊销、维护者/缓存/对象版本/备份全副本删除证明、清当前语音会话接线均是后续集成项，不在本 PR 假造完成。

## 复现

不启动 AVD/手机/云调用。机器已有 Kotlin/JUnit Gradle 缓存时：

```bash
scripts/with-build-lock python3 scripts/test-m09-core.py --out build/m09-core/baseline.json
scripts/with-build-lock python3 scripts/test-m09-core.py --negative-controls --out build/m09-core/negative-controls.json
```

统一既有 `/var/lock/little-buddy/heavy.lock`，单进程、编译内存 768MiB；锁忙退出 75，不另建锁。脚本直接编译真实 main Kotlin 核心和 JUnit 测试，不使用 M02 内存双件，不需要 Android SDK。AndroidFeedbackVault 和 APK 编译不在该命令分母中；后续标准 Gradle 使用同一锁和 `--max-workers=1`。

负控分别破坏较早截止、恢复缺账本拒绝、最终授权（submit/clear 各一次）、完整删除回执。负控必须编译成功且指定反例失败，编译失败不算检测有效。证据 JSON 给逐文件 SHA256、分母、失败与跳过；最终冻结 SHA/tree 和实测结果另列交付记录。
