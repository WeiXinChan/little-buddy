# 瓦力 V1 总体设计

依据 [需求基线](../requirements.md)。本文为评审稿，架构和参数均为推荐起点。设备行为、童声表现、地域网络和服务数据条款以验证结果为准。执行与验收见 [分期开发计划](development-plan.md)。

## 前台音频与交互

横屏亮屏，始终可触及停止。普通触摸立即叠加短表情，结束时由当前状态重新渲染。麦克风权限被拒、音频焦点丢失、路由变化导致录音失效时，由同一清理路径释放音频；可重新显式开始，按权限状态显示引导。失去顶层前台、锁屏或系统中断时清空并释放；恢复后仅重新待机。播放前取得焦点，播放结束或停止时归还。音频所有权由一个协调器串行切换，录音和播放互斥。

- 待机使用一个 16 kHz、单声道 PCM16 AudioRecord，同时向 KWS 和端上内存环形缓冲送帧。约 3 秒缓冲是实验起点；每帧携带单调采样位置。KWS 命中后按关键词结束时间映射到采样位置，回读尾部、保留保护区并接续同一个录音流。快照与订阅在同一顺序队列交接，以绝对帧位置去重并检测缺口。
- 命中后先保留音频，短观察窗内若唤醒词后有语音，连续采集指令并流式发送已触发窗口；指令分支不插播唤醒回应。后端只清理转写开头已确认的唤醒词，指令其余部分保留。时间边界不准时扩大有限保护区并验证漏首字、重复词和紧贴发音。前置窗口和实时帧交接按下文封口协议处理。帧缺口走显式重试，连续音频的低置信结果走简短确认。
- 若观察窗结束且没有后续语音，停止录音、清除缓冲、播放内置简短回应。等实际播放结束和音频资源释放后自动开始新轮聆听。短观察窗、保护区和播放后防回授间隔均通过 OPPO 真机时序测量校准，尤其验证孩子边想边开口和紧接回应说话。
- 开始说话使旧会话失效，清完旧输出后开启新录音。录音启动成功且收到帧后点亮聆听表情。端上 VAD 判定语音开始与结束，允许思考停顿。手动结束走同一封口路径，仅处理有效语音。无有效语音时不提交对话轮；连续无回应只温和追问一次，再超时则退出。正常答复播放排空并得到后端提交确认后自动聆听。告别播放完即清空，停止键随时可跳过。
- 普通轮只上传检测到语音的有界窗口，含短预卷和必要尾部；游戏依赖网络。断网、超时、识别失败结束旧交流，播放本地固定提示并提供显式重试。待机网络连接可预建立，仅传心跳；断开不续传。网络恢复后可开始新交流，本地表情和触摸一直可用。

## 状态与事件

状态包含 `Inactive`、`WakeIdle`、`WakeFollowup`、`StartingCapture`、`Listening`、`Waiting`、`Speaking`、`CleaningUp`、`AudioUnavailable`。网络与权限为入口条件，聊天／游戏模式独立于音频状态。音频所有权以资源确认事件为准。

| 事件 | 转移及条件 |
| --- | --- |
| 前台可用 / 退后台、锁屏 | 进入本地待机 / 立即失效并释放到 Inactive |
| 唤醒命中 / 观察窗到期 | WakeIdle → WakeFollowup → Listening 或本地回应 |
| 开始说话 / capture_ready | 空闲槽位先占用再异步打开 → StartingCapture → 成功且收到有效采集帧后进入 Listening |
| VAD 或手动结束 | Listening → 停收并封口 → Waiting，空语音进入无回应路径 |
| 收到可播放音频 / 播完 | Waiting → Speaking，只有当前轮可播。播尽后等当前轮提交确认，再进入下一轮或待机 |
| 停止 / 超时 / 断网 | 即刻撤销有效身份并清输出，CleaningUp 确认资源归还后进入前台待机或 Inactive，超时进入 AudioUnavailable |

每次新会话分配随机 `sessionId`；`turnId` 在会话内递增；本地 `generation` 在取消、替换、清理开始时增加。全部异步生产者在创建时固定身份，回调经同一串行事件队列，只对当前身份和允许状态有效（包括 UI、错误、VAD、计时器和播放完成）。资源释放完成以协调器操作号关联，不能重新进入已取消轮次。

### 停止与音频重建

1. 在串行协调器上先撤销会话与轮次身份，关闭录放数据入口，立即静音当前输出，清空待播和表现队列。写入采用有界非阻塞分片，停止可立即抢在下一次写入前生效。发起停止、清空、释放和读写任务退出，另行尽力发送取消。可闻静音与资源释放完成分别计时。
2. 录音和播放共享一个槽位，覆盖待机唤醒。协调器在派发异步打开之前原子分配唯一打开操作号并占槽，状态为 `Opening`。槽位按操作号经历 `Opening` → `Owned` → `Releasing` → 空闲，取消中的打开保持占槽。只有打开成功且身份仍有效才把句柄交给录放任务。打开操作对资源结果的回报独立于可取消的业务协程，即使业务已失效也必须交回打开结果。
3. 停止、锁屏、退后台、撤权或超时撤销旧意图，并同时使已有排队开始失效。异步打开未返回时请求取消，槽位继续由原操作占用。只有匹配操作确认失败且所有部分资源已清理，或确认取消且此后不会产生句柄，才能直接归还槽位。发出取消、等待者退出或到达超时均不足以归还。失败伴随部分句柄或迟到成功时，仍由该操作占槽并进入 `Releasing`，仅停止释放所返回的句柄，不启动录放。释放需匹配打开操作号、句柄 ID 与清理操作号，并确认读写任务退出、句柄停止和释放完成，才归还原槽位。重复确认幂等，过期或不匹配确认不得归还新槽位。
4. 清理中至多接纳一个最新的前台显式开始请求，绑定发出时的生命周期和代际。槽位归还只通知资源状态变化，由协调器重新仲裁。只有仍有效的请求满足前台、权限、当前路由与扬声器尾音保护条件，才可重新占槽并打开。迟到回调不可恢复旧会话、改变表现或直接启动录音。恢复前台默认等待唤醒。
5. 清理超时进入 `AudioUnavailable`，清除排队请求并保留原槽位，直到收到上述匹配确认。显式重试可检查清理进度，未确认归还时保持不可录，必要时提示退出并重新打开应用。旧操作最终归还后可重新评估可用性，已失效的排队请求不会恢复。重开仍需系统成功取得音频资源。

## 流协议与上下文

WSS 混合版本化 JSON 控制帧和二进制 PCM。控制帧含 `v`、`sessionId`、`turnId`，音频另含序号、方向、下行分段号与采样位置。端到端校验连接归属、身份、顺序、帧长度和终止状态。连接写入使用单一有界队列，服务端按会话顺序处理状态变更，供应商回调保持异步并带原身份。

### ASR 就绪与封口

1. 待机保护区和普通轮预卷都留在端上。端上 VAD 确认有效语音后才排队发 `turn.start`，后端才打开 ASR 任务。连续唤醒的有效语音判据只查关键词后的区间，上传窗口可含有限保护区。空音频或唤醒词独说不会创建 ASR 任务、发送 PCM 或推进玩法。
2. 等 WSS 鉴权及 ASR 任务确认就绪期间，PCM 只写入端上有界 FIFO，按绝对采样位置接续，每帧只归入一次。后端收到供应商就绪信号才发当前轮 `turn.ready`。此前不发 PCM 或 `turn.end`。
3. 手动结束或 VAD 到端点时停止采集，固定最后一个样本之后的位置。就绪尚未到达时保存封口标记及缓存，等待同一个就绪期限。就绪后按采样位置先发完缓存，再发后续帧，最后发送一次带末尾采样位置的 `turn.end`。后端验证连续性和末尾位置，待供应商写队列排空才向 ASR 发结束指令一次。重复相同封口幂等，冲突、缺帧和序号错误终止本轮。只用最终转写推进对话。
4. 缓存超限、等待就绪超时或发送失败均终止旧会话，释放缓存并提示显式重试。停止和生命周期撤销优先于待发 PCM 与封口，清除未发内容及标记；已发内容由后端按 cancel、断连或连接租约失效清理。取消后到达的 ready 不恢复上传。零有效语音走一次追问路径，低置信转写请求确认，服务故障走显式重试。

### 播放确认与玩法提交

- LLM 文本组成短完整语义段，逐段通过安全检查再送 TTS。正文、语音和一般表情独立流式到达。每段先发 `reply.segment_start`，含顺序编号和必要业务元数据（如揭晓的题目 ID、图片 ID），再发送 PCM。段尾用 `reply.segment_end` 声明总采样数，整轮用 `reply.end` 声明最终段号。一般 `reply.effect` 只在当前代际和允许窗口执行。揭晓图片由分段元数据驱动。
- 安卓将采样位置映射到本次 AudioTrack 句柄的播放头，按段匹配 `segment_end`、PCM 连续性和实际播放进度。只有播放头在有效轨道上走过段末，且未被停止、flush 或换轨，才发送带当前身份和段号的 `playback.segment_completed`。写入结束、收到 `reply.end` 或估算计时到点均不构成播放确认。
- 后端只接受当前连接、当前轮、已发送完整且连续的段 ACK。按段号记录已听前缀，返回 `playback.segment_committed`。同一段重发 ACK 只返回已有确认，缺前序、段未发送完整或段号无效的 ACK 不计入前缀。安卓凭当前揭晓段的回执展示图片一次。此回执只确认该段，题数、下一题和模式变化暂存于本轮。
- 服务端仅在完整发送连续的 1…N 段后声明有效的 `reply.end(finalSegment=N)`，N 为正整数，声明成功后不追加段。只有最终段号已声明、从 1 到 N 的有效播放 ACK 连续齐全、当前轮仍有效，才在同一会话串行处理步骤中一次性应用暂存的游戏变化、提交本轮并发 `turn.committed(N)`。先收到全部 ACK 再声明、先声明再收到最后 ACK，均在第二个条件满足时提交。当前已发送段全部确认但 N 尚未声明时仍留在当前轮。安卓收到匹配的整轮回执，且已收到同一 N 的结束声明、全部段已完整播放并排空后，只推进一次。后端拒绝过早的下一轮 start。
- 相同结束声明与相同整轮回执幂等。服务端以会话及轮次标识去重，只在原连接和会话仍有效时答复已提交轮的重复确认，绝不重放进度变化。冲突结束声明、宣告时有缺段或宣告后追加段属于协议错误，终止当前会话。ACK 缺失或乱序时不补推断，连续前缀始终未齐则按截止时间失败。播放头停在段内时记作「未说完」，只把已确认的连续前缀视为已听到。停止、重开、断连或致命超时先撤销轮次，丢弃临时文本、音频、表现及未提交的玩法变化，并清除会话状态。撤销后到达的 ACK、结束声明及回执均无效。

### 截止时间与半开连接

下表数值是初始配置假设，等待 OPPO、家庭网络及服务器压测校准。阶段计时使用单调时钟，有效进展可重置阶段计时，不能延长整轮上限。

| 截止项 | 建议起点与判定 |
| --- | --- |
| 建连和就绪 | WSS 建连及鉴权 3 秒，发起 ASR 任务后就绪 3 秒。未就绪缓存最多约 3 秒 PCM，独立于待机环形缓冲；任何上限先到即终止。就绪后的发送积压上限约 1 秒 PCM，分批发送缓存并受写入期限控制 |
| 采集和首包 | 起始无语音约 6 秒，仅有效语音才进入上传；尾静音约 0.8 秒，采集最长约 20 秒。端上封口后 8 秒仍无有效可播 PCM 则失败，涵盖等就绪、ASR final、LLM 与 TTS |
| 首段后的流与提交 | 首 PCM 后无网络有效进展约 4 秒触发断流，进展限于连续 PCM 或推进协议的段尾、整轮结束。收到有效最终段声明、本地播放排空且等待整轮提交回执约 3 秒超时。网络已正常完整结束时停用段间计时，播放仍受整轮约束 |
| 整轮与资源清理 | 从有效语音触发起整轮约 45 秒，涵盖就绪、采集、生成、播放和提交。App 音频资源清理约 2 秒，服务端上游取消/关闭约 2 秒，超时后丢弃旧业务回调；音频按重建规则进入不可用，仍处理匹配的资源归还确认，若上游关闭尚未确认则保留占用计数并拒绝相应新调用 |
| 心跳与会话 | 建连后每约 5 秒发带序号的应用心跳，对端回复。每端距最后一次匹配回复约 15 秒即失效，心跳与内容进展分别计时。无活动轮的会话空闲清除约 60 秒，最近 4 轮已确认内容并设字数上限 |

每个设备仅有一个已授权活动连接、一个业务会话和一个活动轮。新连接认证完成后原子撤销同设备旧连接的所有权，在服务端清除旧会话和队列；无新连接时由心跳租约触发同一清理。限制 ASR、LLM、TTS 每类各一个在途任务，含尚未确认关闭的任务，并在适配器配置有限的 I/O 与请求生命周期。旧任务无法确认终止时，该类适配器暂不可用，提示显式重试，避免挂起任务占额时继续发起调用。所有计时器、回调和发送都需核验原连接代际及轮次。

首段后断流、提交超时或失联时，停止当前输出并丢弃尚未播完的音频和表现，清除旧会话，给本地失败提示及显式重试。恢复连接只开启新会话。正常播过的前缀与失败原因仅参与当前轮的内存处理，故障指标无需正文。

## 猜动物与内容控制

固定审核题库每条有动物 ID、同义词、递进线索、图片及授权来源。服务端无放回抽取，保存已出集合和完成数。建议首批至少 12 题。替补耗尽时告知并结束本局，保留跳过不计完成的规则。三题完成后仅明确答应才开新局。

高优先级依次处理安全、退出/切换、提示/不知道/跳过、答案、偏题。规范化同义词，空白、冲突、模糊或转写不确定先确认；猜错给新线索，连续猜错或线索耗尽就询问是否揭晓。孩子拒绝后仍可猜或跳过。线索用尽后用简短鼓励保留猜测、跳过和退出入口，不循环重复线索或揭晓邀请。猜对或揭晓才增加完成数。允许短暂接话后回到题目，明确想聊天即清局。游戏以审核过的固定话术和题库为主，自然意图分类只接受限定枚举与题库 ID，低置信回退到确认。

聊天限制 1–3 个短句，先对输入做安全分流，每个语义段过输出规则再允许合成。身体不适、受伤、害怕及危险要求用固定短句引导找家长，疑似风险时优先用审核话术。模型无工具访问或设备控制权限，表情仅使用白名单。云服务失败时用本地提示并退出旧会话。

## 隐私与运行

麦克风待机环形缓冲只在手机内存，未命中滚动覆盖；上传只在唤醒/显式开始后的有效会话及续轮触发。App 和服务仅在内存处理当前会话，结束、锁屏、断线、崩溃重启或 TTL 到期清除引用；禁用正文追踪、请求体日志、崩溃附件和 core dump，检查代理、SDK、系统转储与交换分区的落盘风险，正式语音服务须验证进程内存不会写入未受控交换空间。日志仅聚合耗时、状态、计数、错误码、版本和计费用量；不用固定儿童标识。测试证据也仅提交指标和脱敏事件轨迹。

后端机密由用户授权注入，保存在应用目录外；APK 中没有服务密钥。一次性管理员配对码换取单设备可撤销凭据，客户端以 Android Keystore 保护本地凭据，再换短效连接令牌；令牌不放 URL 或日志。私有访问优先，只在用户授权后配置 TLS 接入；应用限制连接数、请求大小、速率和用量。签名和配对由成人在安装时完成。
